# Proposal

## Why

0.2.9의 자동 가져오기에는 설치 경로 이탈, 필수 파일 누락 후 성공 처리, 실패 시 기존 인스턴스 변경, 설정 명령 유실 문제가 있다. 일부 모드 로더와 Minecraft 버전은 실행할 수 없는 메타데이터 또는 Java 설정을 생성한다. 자동으로 반복 실행되는 앱이므로 개별 예외 처리보다 설치·기록·화면의 성공 조건을 함께 정리해야 한다.

2026-09-30 전체 코드 점검에서 수정 대상 21건을 정리했다. 근거와 재현 결과는 [점검 보고서](../../reviews/2026-09-30/code-review.md)에 기록한다. 이 change는 개선 요구사항과 구현 계획이며, 현재 구현이 요구사항을 충족한다는 선언이 아니다.

## What Changes

- 압축·매니페스트 경로를 공통 검증하고, 지원하는 형식만 사전 검사 후 설치한다. (R01, R20)
- 필수 다운로드와 캐시의 해시를 검증하고, 설치를 준비·확정·복구 단계로 분리한다. 재가져오기는 사용자 데이터를 보존한다. (R02–R05, R14, R15)
- 설정 명령, 파일 감시, 원본 식별, 재시도를 명시적인 작업 상태로 관리한다. (R06–R08)
- 이력 변경과 디스크 저장을 직렬화하고, 설치 확정과 이력 저장 사이의 중단을 복구한다. (R09)
- Prism 데이터 디렉터리, 프로세스 상태, 로더 UID, Java 버전을 검증한다. (R10–R13, R21)
- 작업 ID와 단계로 진행 상태를 표시하고, 업데이트 실행을 하나로 제한하며 실제 오류 원인을 안내한다. (R16–R19)
- 회귀 테스트, Windows 빌드 검증, 개발·배포 문서를 추가한다.

## Capabilities

### New Capabilities

- `safe-import-paths`: 원본 형식 사전 검사, 경로 범위와 파일 쓰기 검증.
- `reliable-modpack-install`: 검증된 다운로드, 일정한 덮어쓰기 순서, 사용자 데이터 보존, 설치 복구.
- `import-orchestration`: 원본 식별, 작업 스케줄링, 설정 적용 확인, 감시 폴더 전환.
- `durable-import-history`: 원본별 단일 상태, 원자적 저장, 기존 이력 이전과 중단 복구.
- `launcher-runtime-integration`: 선택한 Prism과의 연결, 안전한 재시작, 로더·Java 호환성.
- `desktop-operation-status`: 작업별 진행 표시, 업데이트 단일 실행, 정확한 실패·창 상태 안내.

### Modified Capabilities

없음. 기존 OpenSpec 기준 명세가 없으므로 여섯 capability를 신규 delta 명세로 작성한다. 구현과 검증이 끝난 뒤 기준 명세에 반영한다.

## Impact

- Rust: `watcher.rs`, `tracker.rs`, `config.rs`, `prismlauncher.rs`, `mrpack.rs`, `java.rs`, `lib.rs`와 신규 공통 모듈.
- 화면: `src/main.js`, `src/index.html`, `src/update-blocked.html`, 필요한 Tauri 권한.
- 데이터: 이력 schema version과 원본→인스턴스 매핑, 설치 journal 도입. 기존 데이터는 백업하고 모호한 매핑은 확인이 필요한 상태로 남긴다.
- 동작: 잘못된 팩, 불완전한 설치, 불명확한 프로세스 상태는 성공으로 처리하지 않는다. 재시도할 수 있는 이유를 표시한다.
- 비용: 설치 준비와 롤백에 추가 디스크 공간이 필요하다. 설치 완료를 알리는 시점은 Java 및 이력 저장 검증 이후로 바뀐다.
- 범위: Windows를 우선 검증한다. 새 화면 디자인, 새 모드팩 형식, 계정·클라우드 서비스 추가는 이번 변경에 포함하지 않는다.
