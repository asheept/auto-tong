# Spec Delta

## Purpose

파일 변경 감지와 사용자 명령을 일관된 가져오기 작업으로 연결하고, 설정 변경이나 같은 파일명의 여러 원본 때문에 작업이 유실되거나 다른 인스턴스가 바뀌는 일을 방지한다.

## ADDED Requirements

### Requirement: 설정 변경의 확실한 반영

시스템은 중복 스캔 요청을 합칠 수 있지만 설정 변경·재시도·취소 명령을 버리지 않아야 한다(MUST). 저장한 설정이 실행 중인 감시에 적용되었는지 구분하여 알려야 한다(SHALL). 설정 저장과 적용은 하나의 버전으로 추적해야 한다(SHALL).

#### Scenario: 스캔 대기 중 설정 변경

- **WHEN** 스캔 요청이 연속으로 들어오는 동안 사용자가 감시 폴더와 태그를 바꾼다
- **THEN** 최신 설정이 적용되며 적용 확인 전에는 적용 완료로 표시하지 않는다

#### Scenario: 감시 폴더 교체

- **WHEN** 감시 폴더 설정이 A에서 B로 적용된다
- **THEN** A의 감시를 해제하고 B에 감시를 등록하며 한 시간 주기 재등록을 기다리지 않는다

#### Scenario: 새 폴더 감시 실패

- **WHEN** 새 폴더의 파일 이벤트 감시 등록에 실패한다
- **THEN** 등록 실패와 폴링 대체 상태를 표시하고 이전 폴더가 새 폴더인 것처럼 표시하지 않는다

### Requirement: 원본과 대상의 고유한 연결

시스템은 정규화한 감시 루트와 상대 경로를 포함해 원본을 식별하고 각 원본에 고유한 인스턴스를 연결해야 한다(SHALL). 파일명의 같음이나 초 단위 수정 시간의 같음만으로 다른 콘텐츠를 동일하게 취급하지 않아야 한다(MUST).

#### Scenario: 같은 이름의 다른 팩

- **WHEN** `a/pack.zip`과 `b/pack.zip`이 같은 감시 루트에 있다
- **THEN** 두 원본은 서로 다른 인스턴스로 연결되며 한쪽 가져오기가 다른 쪽을 덮어쓰지 않는다

#### Scenario: 루트 또는 콘텐츠 변경

- **WHEN** 같은 상대 경로의 감시 루트가 바뀌거나 수정 시간이 같은 파일의 내용이 바뀐다
- **THEN** 해당 원본과 콘텐츠를 다시 판별하고 이전 성공 이력만으로 건너뛰지 않는다

### Requirement: 원본별 작업 직렬화와 재시도

시스템은 같은 원본을 동시에 설치하지 않아야 하며 안정화된 원본 스냅샷을 설치해야 한다(MUST). 작업 도중 원본이 바뀌면 변경본을 후속 작업으로 처리해야 한다(SHALL). 일시적인 실패는 제한된 자동 재시도와 명시적인 수동 재시도를 지원해야 한다(SHALL).

#### Scenario: 원본을 복사하는 중

- **WHEN** 파일 크기 또는 내용이 관찰 도중 바뀐다
- **THEN** 불완전한 원본을 성공 처리하지 않고 안정화된 스냅샷을 기다린다

#### Scenario: 변경되지 않은 파일의 일시적 실패

- **WHEN** 네트워크 장애가 복구된 뒤 사용자가 실패 작업을 재시도한다
- **THEN** 원본의 수정 시간을 바꾸거나 기존 성공 이력을 삭제하지 않아도 다시 시도한다

### Requirement: 빈 태그의 명시적 처리

시스템은 공백 또는 접두사 제거 후 빈 문자열이 되는 태그를 유효한 필터로 저장하지 않아야 한다(MUST).

#### Scenario: 빈 태그 저장

- **WHEN** 사용자가 `@` 또는 공백만 있는 태그를 저장한다
- **THEN** 입력 오류를 표시하며 모든 파일에 일치하는 필터로 적용하지 않는다
