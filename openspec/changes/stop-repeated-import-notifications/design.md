# 설계와 동작 범위

## 알림과 보류

감시 작업 하나가 원본별 오류와 Prism 데이터 루트별 복구 오류 상태를 공유한다. 같은 미해결 오류는 실행 중 한 번만 알리고, 복구 성공 또는 실제 콘텐츠 변경 뒤 새로 발생한 오류는 다시 알린다. 대기 시간이나 재시도 횟수 제한 때문에 작업을 건너뛴 것을 오류 해결로 취급하지 않는다. 삭제된 원본의 상태를 정리해도 데이터 루트의 복구 오류 상태는 유지한다.

가져올 필요가 있는 원본에 대해서만 런처를 비파괴적으로 확인한다. 게임 실행·조회 실패·실행 파일 누락이면 snapshot 및 설치 준비 전에 보류한다. 첫 보류만 진행 상태와 알림을 생성한다. 게임이 실행되지 않고 런처가 정상 조회되면 자동 진행한다. 설치 확정 도중 보류된 경우는 런처까지 종료된 상태를 확인한 뒤 자동 재개하여 실패한 종료 시도를 매 스캔 반복하지 않는다. 기존 설치 직전 검사와 정상 종료 절차는 유지한다.

## 실패 기록과 재시도

임시 설치 폴더 준비 실패도 기존 30초·120초 재시도 및 총 3회 한도에 포함한다. 저장 실패는 최종 RecoveryRequired/Storage 상태로 남기고 후속 Failed 이벤트로 덮지 않는다.

실패/취소 이력을 디스크에 기록하지 못하면 Tracker의 별도 실행 중 보호 상태가 같은 원본의 같은 콘텐츠를 막는다. 보호 상태와 데이터 갱신은 같은 잠금 순서를 사용한다. 저장하지 못한 성공이나 실패 이력을 정상 저장된 것처럼 공개하지 않는다. 기록 저장이 성공한 명시적 재시도, 정상 기록 또는 실제 콘텐츠 변경으로 보호 상태를 해제한다.

실패 콘텐츠는 크기와 SHA-256으로 비교하여 동기화 과정의 수정 시각 변경만으로 재시도 횟수가 초기화되지 않는다. 정상 설치 기록의 기존 판별과 이력 스키마는 유지한다.

알림 중복 방지와 저장 실패 보호 상태는 메모리에 있으므로 앱 재시작 때 초기화된다. 저장된 일반 실패 횟수는 재시작 후에도 유지된다. 디스크 쓰기 장애 자체를 복구하거나 기존 손상 journal을 자동 제거하지 않는다.

## 최초 journal

새 백업 디렉터리와 journal 임시 파일을 RAII로 소유한 상태에서 Prepared 내용을 완전히 쓰고 동기화한다. 기존 파일을 덮지 않는 persist_noclobber로 유효한 journal을 공개한 다음 백업을 유지하고 실제 인스턴스 이동을 시작한다. 최초 쓰기·공개 실패는 새 임시 자원을 정리하며, 이미 존재하던 기록과 사용자 데이터는 보존한다. 후속 단계의 journal 교체·중단 복구 동작은 유지한다.
