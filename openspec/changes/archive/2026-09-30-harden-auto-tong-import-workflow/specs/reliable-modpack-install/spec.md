# Spec Delta

## Purpose

다운로드와 압축 해제의 완료 여부를 검증하고 설치를 복구 가능한 방식으로 확정하여, 실패한 가져오기가 정상 설치처럼 기록되거나 기존 게임 데이터를 손상시키지 않도록 한다.

## ADDED Requirements

### Requirement: 필수 파일의 무결성

시스템은 설치 대상으로 선택된 모든 파일의 다운로드와 해시 검증에 성공한 경우에만 설치를 확정해야 한다(SHALL). 캐시를 재사용할 때도 내용을 검증해야 한다(MUST). 클라이언트에서 지원하지 않는 파일은 제외하고, 선택적 파일의 포함 정책을 일관되게 적용해야 한다(SHALL).

#### Scenario: 필수 다운로드 실패

- **WHEN** 필수 파일의 모든 다운로드 후보가 HTTP 오류 또는 전송 오류로 실패한다
- **THEN** 파일명과 실패 원인을 표시하고 성공 이력을 남기지 않으며 재시도를 허용한다

#### Scenario: 같은 크기의 잘못된 파일

- **WHEN** 기존 파일 크기는 매니페스트와 같지만 해시가 다르다
- **THEN** 검증된 파일을 다시 확보하거나 가져오기를 실패 처리한다

### Requirement: 일정한 파일 적용 순서

시스템은 다운로드 파일, 공통 overrides, 클라이언트 overrides 순서로 팩 콘텐츠를 적용해야 한다(SHALL). 압축 엔트리 순서는 결과를 바꾸지 않아야 한다(MUST).

#### Scenario: 같은 경로에 여러 콘텐츠 존재

- **WHEN** 다운로드와 두 overrides 계층이 같은 파일을 제공한다
- **THEN** 클라이언트 overrides가 최종 팩 콘텐츠가 되며 ZIP 엔트리 순서를 바꿔도 결과가 같다

### Requirement: 기존 데이터 보존과 설치 복구

시스템은 모든 파일과 실행 환경 검증이 끝나기 전 기존 인스턴스를 변경하지 않아야 한다(SHALL). 설치 확정 실패 또는 중단 후 기존 설치를 복구하거나 검증된 새 설치를 완료할 수 있어야 한다(MUST). 저장한 월드, 스크린샷, 사용자 옵션, 관리 대상이 아닌 파일은 보존해야 한다(SHALL). 사용자가 수정한 파일과 새 팩 파일이 충돌하면 자동으로 덮어쓰지 않아야 한다(MUST).

#### Scenario: 준비 단계 실패

- **WHEN** 파일 일부를 준비한 뒤 압축 해제·다운로드·Java 검증이 실패한다
- **THEN** 기존 인스턴스는 변경되지 않고 실패 상태와 재시도 방법을 표시한다

#### Scenario: 재가져오기

- **WHEN** 사용자가 기존 바닐라·Prism·MRPACK 인스턴스의 재가져오기를 요청한다
- **THEN** 동일한 원본에 매핑된 인스턴스를 대상으로 검증된 설치 절차를 수행하고 사용자 데이터를 보존한다

#### Scenario: 설치 확정 도중 중단

- **WHEN** 기존 설치를 이동한 뒤 새 설치 확정 전에 앱이 중단된다
- **THEN** 다음 실행에서 복구 상태를 먼저 확인하고 정상 설치 하나를 확보한 뒤 자동 가져오기를 재개한다

### Requirement: 유한한 자원 사용과 중단 가능성

시스템은 연결·전송·재시도에 제한을 두고, 압축 해제량과 다운로드량을 제한해야 한다(SHALL). 장시간 작업 중에도 설정 적용과 취소 요청을 처리해야 하며, 취소한 작업을 성공으로 기록하지 않아야 한다(MUST).

#### Scenario: 응답이 멈춘 서버

- **WHEN** 서버가 제한 시간 동안 응답 데이터를 보내지 않는다
- **THEN** 작업은 제한된 횟수만 재시도하고 실패 이유를 표시하며 다른 제어 요청을 계속 처리한다

#### Scenario: 설치 중 취소

- **WHEN** 사용자가 준비 중인 작업을 취소한다
- **THEN** 준비 파일을 정리하고 기존 인스턴스를 보존하며 취소 상태를 표시한다
