# desktop-operation-status Specification

## Purpose

가져오기와 업데이트의 진행·완료·실패 상태를 실제 작업 수명에 맞게 표시하고, 중복 업데이트나 창 복구 실패 때문에 사용자가 잘못된 조치를 취하지 않도록 한다.

## Requirements

### Requirement: 작업별 진행과 완료 표시

시스템은 각 작업을 고유하게 식별하고 준비·다운로드·Java 검증·설치 확정·이력 저장·종료 상태를 구분해 표시해야 한다(SHALL). 이전 작업의 이벤트와 타이머가 현재 작업의 화면을 숨기지 않아야 한다(MUST). 완료는 설치 및 이력 저장 이후에 표시해야 한다(SHALL).

#### Scenario: 연속 가져오기

- **WHEN** 첫 작업의 완료 표시가 사라지기 전에 다음 작업이 시작한다
- **THEN** 이전 타이머는 새 작업의 진행 표시를 숨기지 않는다

#### Scenario: 다운로드 후 Java 준비

- **WHEN** 다운로드가 끝났지만 Java 준비 또는 이력 저장이 진행 중이다
- **THEN** 해당 단계를 표시하며 전체 가져오기를 완료로 표시하지 않는다

### Requirement: 업데이트의 단일 실행

시스템은 시작 시 자동 검사와 수동 검사에서 같은 업데이트 작업 상태를 공유해야 하며 한 번에 하나의 설치만 수행해야 한다(MUST). 화면은 실제 업데이트 상태를 반영해야 한다(SHALL).

#### Scenario: 자동 설치 중 수동 검사

- **WHEN** 자동 업데이트가 설치 중이고 사용자가 다시 검사를 요청한다
- **THEN** 진행 중인 작업을 표시하고 두 번째 다운로드·설치를 시작하지 않는다

### Requirement: 원인에 맞는 업데이트 오류 안내

시스템은 네트워크, 서명, 디스크, 권한, 설치 프로그램 실행 실패를 구분 가능한 범위에서 안내하고 나머지는 미분류 오류로 표시해야 한다(SHALL). 단순 실패 횟수만으로 운영체제 보안 기능의 차단이라고 단정하거나 보안 기능을 끄도록 안내하지 않아야 한다(MUST).

#### Scenario: 반복되는 네트워크 실패

- **WHEN** 업데이트 다운로드가 연속 두 번 네트워크 오류로 실패한다
- **THEN** 네트워크 원인과 재시도 또는 공식 수동 다운로드 경로를 표시한다

### Requirement: 안내 창의 닫기와 다시 열기

시스템은 안내 창의 닫기 버튼을 허용된 창 동작으로 처리하고 숨겨진 기존 창을 다시 표시할 수 있어야 한다(SHALL).

#### Scenario: 안내 창 재사용

- **WHEN** 사용자가 안내 창을 닫은 후 같은 안내를 다시 연다
- **THEN** 안내 창이 화면에 표시되고 포커스를 받으며 닫기 동작의 권한 오류가 발생하지 않는다
