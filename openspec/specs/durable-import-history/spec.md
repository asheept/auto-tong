# durable-import-history Specification

## Purpose

설치 상태와 이력을 디스크에 일관되게 보존하여 저장 실패, 동시 변경, 이전 버전 데이터, 실행 중단이 잘못된 성공 표시나 불필요한 재설치로 이어지지 않도록 한다.

## Requirements

### Requirement: 저장과 현재 상태의 일치

시스템은 원본마다 하나의 현재 상태를 유지하고, 지속 저장에 성공한 변경만 확정된 이력으로 공개해야 한다(SHALL). 설치 상태와 최근 시도 결과를 구분해야 한다(SHALL). 저장 오류를 사용자에게 알려야 하며 성공 알림으로 숨기지 않아야 한다(MUST).

#### Scenario: 이력 저장 실패

- **WHEN** 디스크 또는 권한 문제로 이력 파일 저장에 실패한다
- **THEN** 저장된 것처럼 성공 이력을 표시하거나 재시도를 억제하지 않고 복구가 필요한 상태를 표시한다

#### Scenario: 재가져오기 실패

- **WHEN** 기존 정상 설치가 있는 원본의 새 가져오기가 실패한다
- **THEN** 기존 설치는 유지되며 해당 원본 한 항목에 현재 설치와 최근 실패 결과를 구분해 표시한다

### Requirement: 동시 변경과 재시작의 일관성

시스템은 서로 다른 이력 변경을 유실 없이 보존하고 저장 도중 중단되어도 마지막 정상 이력 또는 복구 가능한 기록을 제공해야 한다(SHALL).

#### Scenario: 완료 기록과 재시도가 겹침

- **WHEN** 작업 완료 기록 중 다른 원본의 재시도 요청을 저장한다
- **THEN** 두 변경 모두 재시작 후 유지되며 임시 파일 이름 충돌로 유실되지 않는다

#### Scenario: 설치 확정 후 이력 저장 전 중단

- **WHEN** 새 설치가 확정된 직후 앱이 중단된다
- **THEN** 다음 실행에서 설치 기록과 실제 설치를 대조하여 이력을 복구하며 무조건 다시 덮어쓰지 않는다

### Requirement: 이전 이력의 보존과 이전

시스템은 기존 이력을 백업하고 식별 가능한 항목만 새 원본 식별 체계로 이전해야 한다(SHALL). 손상되거나 매핑이 모호한 이력을 빈 정상 이력으로 취급하지 않아야 한다(MUST).

#### Scenario: 손상된 이력

- **WHEN** 기존 이력 JSON을 읽거나 해석할 수 없다
- **THEN** 원본과 복구 가능한 백업을 보존하고 오류를 표시하며 전체 팩의 자동 재설치를 시작하지 않는다

#### Scenario: 같은 이름에 여러 후보 존재

- **WHEN** 이전 상대 경로 이력에 대응할 원본 또는 인스턴스를 하나로 결정할 수 없다
- **THEN** 확인이 필요한 상태로 남기며 임의의 인스턴스를 연결하거나 삭제하지 않는다
