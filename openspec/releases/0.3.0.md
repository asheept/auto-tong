# Auto-Tong 0.3.0 배포 기록

2026-09-30 요청에 따라 공개 버전 0.2.9의 후속 버전 0.3.0을 배포했다. 가져오기 개선 내역은 [보관한 검증 기록](../changes/archive/2026-09-30-harden-auto-tong-import-workflow/verification-report.md)에 있다.

## 배포 작업

- [x] Cargo·Tauri·npm 및 두 잠금 파일의 제품 버전을 0.3.0으로 맞추고 `v0.3.0` 태그 일치 검사를 통과한다.
- [x] 고정된 이전 버전에 의존하던 버전 테스트를 수정하고 JavaScript 테스트 8개 및 Rust 형식 검사를 통과한다.
- [x] 버전 변경 커밋의 Windows CI를 통과한다.
- [x] 검증한 PR #1을 master에 병합하고 원격 반영을 확인한다.
- [x] master의 배포 커밋에 v0.3.0 태그를 push하고 Release workflow의 성공을 확인한다.
- [x] 공개 릴리스의 설치 파일·서명·latest.json과 앱의 최신 업데이트 주소가 0.3.0을 가리키는지 확인한다.

## 변경 요약

- ZIP·MRPACK의 경로·형식·다운로드 무결성을 검증한다.
- 가져오기 실패와 중단에서 기존 설치·월드·옵션을 보존하고 복구한다.
- 원본별 설치 이력, 감시 설정 적용, 제한된 재시도와 취소를 정리한다.
- Minecraft에 맞는 Java를 검증하고 게임 실행 중 설치 확정을 보류한다.
- updater 중복 실행을 막고 오류 안내와 안내 창 재열기를 개선한다.

## 검증 근거

- `node scripts/check-version.js v0.3.0`: 통과.
- `cargo metadata --locked --offline --no-deps`, `cargo fmt --all -- --check`: 통과.
- Node 테스트 8개: 통과. Cargo 잠금 파일의 변경은 제품 패키지 버전 한 곳이다.
- 수정 커밋 `d4d2ee2`의 [Windows CI](https://github.com/asheept/auto-tong/actions/runs/36660017039)가 통과했다. [PR #1](https://github.com/asheept/auto-tong/pull/1)은 master의 `4b4a009`에 병합됐고 원격 master를 확인했다. 병합 커밋의 전체 파일이 검증한 커밋과 같음을 확인한 뒤 `v0.3.0` 태그를 push했다. [master CI](https://github.com/asheept/auto-tong/actions/runs/36660257063)와 [Release workflow](https://github.com/asheept/auto-tong/actions/runs/36660328955)도 모두 통과했다.
- 첫 버전 변경 CI에서는 87/88개 Rust 테스트가 통과했고 캐시 교체 테스트의 로컬 HTTP 요청이 전송 오류로 실패했다. 후속 로컬 실행에서 테스트 서버의 수락 소켓 읽기가 Windows 오류 10035(`WouldBlock`)를 반환하는 것을 확인했다. 수락한 소켓을 명시적으로 blocking 모드로 전환하고 요청 헤더 끝까지 받은 뒤 응답하도록 수정했다. 제품 다운로드 처리와 검증 조건은 유지하며 후속 CI에서 결과를 확인한다.
- 위 fixture 수정 후 로컬 Windows MSVC Rust 테스트 88개와 형식 검사를 모두 통과했다.
- [공개 릴리스 v0.3.0](https://github.com/asheept/auto-tong/releases/tag/v0.3.0)은 draft·prerelease가 아닌 정식 릴리스다. 설치 파일·서명·업데이트 정보 등 아티팩트 9개를 내려받아 크기와 GitHub SHA-256 digest를 확인했다.
- Windows NSIS 설치 파일·NSIS 호환 ZIP·MSI 설치 파일·MSI 호환 ZIP의 서명 4개를 앱에 설정된 공개키와 `minisign-verify 0.2.5`로 검증했다. manifest의 Windows 플랫폼 3개도 각각 같은 공개키로 검증했다. 이는 Tauri updater의 서명 검증 방식과 같다.
- 앱의 `releases/latest/download/latest.json` 주소에서도 공개 아티팩트의 manifest와 동일한 0.3.0 정보를 확인했다. 내려받은 파일과 검증 결과는 `%TEMP%\auto-tong-release-0.3.0\verification.json`에 보존했다.
- 원본 작업 폴더는 파일 내용이 배포 커밋과 일치하고 사용자 staged 변경이 없음을 확인한 뒤 로컬 master를 맞췄다. 작업 폴더의 파일과 기존 생성 schema 파일은 덮어쓰지 않았다.
